# 技能语义参考手册

> 用途：统一技能/计谋牌的描述写法，让 AI（SkillAnalyzer）能稳定识别技能意图。
> 适用范围：`js/skillAnalyzer.js` 的 `analyze(skill)` 与 `analyzeCard(card)`。

---

## 一、AI 是怎么理解技能的

AI 不读你的设计意图，它做两件事：

1. **扫描文本**：把 `contentCode`（DIY 技能源码）和 `desc`（描述）拼在一起做正则匹配；
2. **推断语义**：输出 `{ type, target, power, priority, condition, preferTarget, minTargets, avoidSelf, hpThreshold }`。

因此描述不是给人看的装饰，**它就是 AI 的输入接口**。写法越标准，AI 行为越可控。

若不想依赖自动推断，可以直接提供 `aiHint` 对象，它优先级最高（`source: 'manual'`）。

> ⚠️ **必须带 `type` 字段，否则整份 `aiHint` 会被忽略**（源码判断条件是 `skill.aiHint.type` 存在）。只想改一个字段时，也要把 `type` 一起写上。

```js
{
  id: 'sk_fire', name: '火计', type: '主动',
  contentCode: '...',
  desc: '对范围内所有敌人造成 40 点伤害',
  aiHint: { type: 'damage', target: 'aoe_enemy', power: 40, minTargets: 2 }
}
```

---

## 二、技能对象字段

| 字段 | 类型 | 对 AI 的作用 |
| --- | --- | --- |
| `id` | string | 冷却、限定技记录的唯一键 |
| `name` | string | 日志与调试显示 |
| `type` | `'主动' \| '被动'` | `'被动'` 不参与主动施放评分 |
| `cooldown` | number | 间接决定 `priority`：0→4，1~3→6，≥4→8 |
| `limited` | boolean | 限定技，`priority` 直接给 10 |
| `filter` | function | 返回 false 时 AI 认为该技能不可用 |
| `preview` | `{ shape, n, passThrough }` | AI 用它统计范围内敌我数量；**缺失时退化为"身边 4 格"估算** |
| `contentCode` | string | 自动分析的主要文本来源（优先于 `content`） |
| `content` | function | 内置技能的分析来源（`toString()`） |
| `desc` / `description` | string | 与源码一起参与分析，**是补充语义的最佳位置** |
| `aiHint` | object | 手动语义，优先级最高，可覆盖任何自动推断 |

---

## 三、语义字段详解

### 1. `type` —— 技能类型

按以下**固定顺序**匹配，先命中先返回（顺序决定歧义时的结果）：

| 顺序 | 类型 | 触发关键词（正则摘要） |
| --- | --- | --- |
| 1 | `control` | 眩晕、沉默、冻结、魅惑、嘲讽、禁锢、束缚、定身、stun、silence、freeze、charm、taunt、disable |
| 2 | `teleport` | 传送、瞬移、闪现、teleport、moveTo、setPosition、jumpTo |
| 3 | `summon` | 召唤、summon、spawnPiece、deployMinion |
| 4 | `heal` | 治疗、回复、恢复生命、hp +=、restoreHp、cure |
| 5 | `buff` | 增益、攻击+、防御+、提升…攻击/防御、增加…攻击/防御、buffAtk、buffDef、addMark … atk/def |
| 6 | `debuff` | 减益、攻击-、防御-、降低攻击、降低防御、中毒、燃烧、流血、poison、burn、bleed |
| 7 | `damage` | 伤害、damage、dealDamage、hp -=、造成…伤害、magicDamage、physicalDamage |
| — | `mixed` | 都没命中时的兜底 |

**关键规则**

- 控制优先于伤害：``冻结并造成 30 点伤害`` 会被识别为 `control`，这是刻意设计。
- **不要滥用"伤害"二字**：`免疫伤害`、`伤害减免` 也会命中 `damage`。描述这类效果请写"减免""免疫"，或在 `aiHint` 里显式声明类型。
- **不要用"回复"表示非生命值**：`回复行动力` 会被判成 `heal`。非生命回复请写"恢复行动次数"（注意"恢复生命"才是 heal 关键词，单独"恢复"不匹配；但"回复"单独即可匹配）。

### 2. `target` —— 目标类型

按顺序匹配：

| 顺序 | 目标 | 触发写法 |
| --- | --- | --- |
| 1 | `aoe_enemy` | `chooseCell(... mustEnemy ...)`、`aoeEnemy`、`enemyAoE`、`cellsInRange` + enemy、`所有敌人`、`全体敌人`、`每个敌人`、`范围内…敌人` |
| 2 | `aoe_ally` | `chooseCell(... mustAlly ...)`、`aoeAlly`、`allyAoE`、`所有友军`、`全体友军`、`每个友军`、`范围内…友军` |
| 3 | `enemy` | `chooseEnemy`、`chooseCardEnemy`、`targetEnemy`、`pickEnemy` |
| 4 | `ally` | `chooseAlly`、`chooseCardAlly`、`targetAlly`、`pickAlly` |
| 5 | `cell` | `chooseCell(`、`chooseCardCell`、`chooseCardZone`、`chooseCardOwnHalf`、`chooseCardFullField`、`chooseCardEnemyHalf`、`传送到`、`移动到…格` |
| 6 | `self` | `chooseSelf`、`Effect.self`、`actor.hp -=`、`自伤` |

兜底：文本含"伤害"→ `enemy`；含"治疗/回复"→ `ally`；含"友军/队友/友方"→ `ally`；否则 `enemy`。

**标准写法建议**

```js
// 单体敌人
const t = await Effect.chooseEnemy(actor, { range: 2 });
// 群体敌人（先选格再结算）
const c = await Effect.chooseCell(actor, { range: 2, mustEnemy: true });
// 单体友军
const a = await Effect.chooseAlly(actor, { range: 3 });
// 指定区域（卡牌）
const c = await Effect.chooseCardCell(side, { zone: 'enemyHalf' });
```

### 3. `power` —— 效果强度（1~200）

AI 用它换算收益，必须能被解析出来。支持的提取写法（按顺序）：

| 写法 | 示例 |
| --- | --- |
| `dealDamage(目标, N)` | `Effect.dealDamage(t, 40)` |
| `damage = N` | `const damage = 40` |
| `hp -= N` | `t.hp -= 40` |
| `heal(目标, N)` | `Effect.heal(a, 50)` |
| `hp += N` | `a.hp += 50` |
| `atkBuff: N` | `{ atkBuff: 20 }` |
| 描述：`造成 N 点伤害` | `造成 40 点伤害` |
| 描述：`回复 N 点生命` | `回复 50 点生命` |

**无法解析时按类型给默认值**：heal 50 / buff·debuff 25 / control 40 / damage 40 / 其它 30。
→ 依赖默认值会让 AI 严重误判强度，**务必让数值出现在上述任一写法中**。

### 4. `priority` —— 优先级（1~10）

自动由冷却推导：`cooldown = 0` → 4；`cooldown = 1` → 5；`2~3` → 6；`≥4` → 8；`limited` → 10。
打分公式为 `power × (0.5 + priority / 10)`，冷却长的大招天然更"值钱"。一般无需手写。

### 5. `condition` —— 施放前置条件

| condition | 自动识别写法 | AI 行为 |
| --- | --- | --- |
| `always` | 默认 | 无前置限制 |
| `self_low_hp` | `hp < maxHp * 0.3~0.5`、低血量、残血时 | 自身血量高于阈值（默认 40%，可用 `hpThreshold` 覆盖）时**放弃使用** |
| `self_full_hp` | `hp >= maxHp`、满血时、`hp/maxHp >= 0.9` | 未满血时放弃 |
| `ally_injured` | `友军…血量`、`allies.filter(... hp`、injured ally | 没有低于阈值（默认 70%）的友军时放弃 |
| `enemy_near` | `附近…敌人`、`距离 <= 2~4` | 4 格内无敌人时放弃 |
| `enemy_in_range` | `范围内…敌人`、`enemiesInRange` | 技能范围内无敌人时放弃 |
| `has_target` | **只能通过 `aiHint` 指定** | 范围内无敌人时放弃 |

**用法示例**

```js
desc: '自身血量低于 40% 时，回复 60 点生命'
aiHint: { type: 'heal', condition: 'self_low_hp', hpThreshold: 40 }
```

### 6. `preferTarget` —— 目标偏好

只影响 AI 选谁，不影响技能逻辑。自动识别 + 可手动指定的完整取值：

| 值 | 适用 | 含义 |
| --- | --- | --- |
| `low_hp` | 敌方 | 残血优先（补刀） |
| `high_hp` | 敌方 | 高血量优先（削血/百分比伤害） |
| `high_threat` | 敌方/友方 | 威胁最高优先（打主力 / 增益给主力） |
| `nearest` | 敌方/友方 | 最近优先 |
| `farthest` | 敌方 | 最远优先（拉扯、远程消耗） |
| `caster` | 敌方 | 高攻低防的法师优先 |
| `tank` | 敌方 | 高防高血前排优先 |
| `low_def` | 敌方 | 低防目标优先（保证伤害） |
| `minion` | 敌方 | 优先清小兵 |
| `general` | 敌方 | 优先打武将 |
| `injured_ally` | 友方 | 受伤友军优先 |
| `buffer` | 友方 | 增益给主力（等同 high_threat） |

**自动推断只认这几种写法**：`最低血量`/`血量最低`/`最低生命`/`生命最低`/`残血`、`最高威胁`/`威胁最高`/`威胁度最高`、`受伤的友军`/`受伤友军`/`残血友军`、`最近…敌人`/`nearest`、`法师`/`caster`/`高攻低防`。
其余取值（`farthest`、`tank`、`minion`、`general`、`low_def`、`high_hp`、`buffer`）**必须通过 `aiHint` 指定**。

### 7. `minTargets` —— 最少命中数

- 写法：`至少命中 N 个` 或 `minTargets: N`；
- 文本含群体词（`aoe`、`所有敌人`、`全体敌人`、`每个敌人`、`所有友军`、`全体友军`、`allEnemies`）时默认要求 **2** 个目标；
- 未命中数量要求时，AI 直接放弃施放。

群体技能强烈建议显式写 `至少命中 2 个`，否则会出现"对着一个敌人放大范围技能"的浪费。

### 8. `avoidSelf` —— 排除自己

- 写法：`不包含自己`、`排除自己`、`excludeSelf`；
- 作用：AI 选择目标时跳过施法者本人（自伤/嘲讽类技能要注意）。

### 9. `hpThreshold` —— 血量阈值（百分数 0~100）

- 写法：`hp / maxHp < 0.4`、`hp < maxHp * 0.4`、`血量低于 40%`；
- 同时作用于 `self_low_hp` 与 `ally_injured` 的判定阈值。

## 四、标准描述模板

推荐一句话包含 **类型 + 目标 + 数值**，必要时补 **条件 / 偏好**：

```
[条件]，对[目标范围][目标类型]造成/回复/施加 [数值][效果]。
```

| 场景 | 推荐写法 | 会被解析为 |
| --- | --- | --- |
| 单体伤害 | 对一名敌人造成 40 点伤害 | damage / enemy / 40 |
| 群体伤害 | 对范围内所有敌人造成 30 点伤害，至少命中 2 个 | damage / aoe_enemy / 30 / minTargets 2 |
| 单体治疗 | 回复一名友军 50 点生命 | heal / ally / 50 |
| 群体治疗 | 为范围内所有友军回复 30 点生命 | heal / aoe_ally / 30 / minTargets 2 |
| 攻击增益 | 提升一名友军 20 点攻击 | buff / ally / 20 |
| 控制 | 眩晕一名敌人，持续 1 回合 | control / enemy / 40 |
| 位移 | 传送到范围内任意空格 | teleport / cell / 30 |
| 斩杀 | 对血量最低的敌人造成 60 点伤害 | damage / enemy / 60 / low_hp |

> 补充：描述中出现"范围内…敌人"时，除目标类型外还会附带 `condition: 'enemy_in_range'`（范围内无敌人则不施放），这通常是符合直觉的；若不想要该限制，用 `aiHint` 显式覆盖 `condition`。
>
> 上表 8 条模板 + 上文"低血量回复"示例，均已用 `SkillAnalyzer.analyze` 逐条跑通，可放心复制。

**禁止的模糊写法**

| 写法 | 问题 |
| --- | --- |
| 造成不俗的伤害 | 无数字，power 落到默认 40 |
| 回复状态 | 会被误判为 heal |
| 免疫伤害 | 会被误判为 damage |
| 对敌人施加压力 | 无任何可识别关键词，落到 mixed |
| 范围攻击 | 缺少数值；建议写"范围内所有敌人"以触发 AOE 判定 |

## 五、计谋牌 / 成略牌的额外语义

`SkillAnalyzer.analyzeCard(card)` 在技能语义之上，额外推断：

| 字段 | 识别写法 | AI 用途 |
| --- | --- | --- |
| `isSummon` | `deployMinion`、`summon`、`召唤`、`spawnPiece` | 召唤收益按兵力差折算 |
| `isControl` | `stun`、`眩晕`、`冻结`、`沉默`、`禁锢`、`定身`、`陷阱`、`placeTrap` | 按敌方威胁×控制时长估值 |
| `isBuff` | `buff`、`增益`、`提升攻击`、`提升防御`、`addMark` | 按增益量估值 |
| `needsTarget` | `chooseCardCell/Ally/Enemy/Zone/FullField/OwnHalf/EnemyHalf`、`chooseOption` | 无合法目标时不出牌 |
| `heavy` | `所有`、`全体`、`范围`、`aoe`、`allEnemies`、`each enemy` | 群体效果加权 |

**计谋牌脚本约定（重要）**

```js
// contentCode 必须显式 return true 才算"使用成功"
const ally = await Effect.chooseCardAlly(side, { zone: 'ownHalf' });
if (!ally) return false;          // 无目标 → 不消耗牌、不扣部署点
Effect.heal(ally, 30);
return true;                       // 提交：扣点数、进弃牌堆、联机同步
```

- 只写 `Effect.heal(...)` 而不 `return true`，AI 会认为"脚本未返回 true"，**不消耗卡牌**（这是防误触的保护）。
- 自动推断依赖 `contentCode` 文本，因此**卡牌描述同样要写清数值**，例如"回复一名友军 30 点生命"。

## 六、自检方法

浏览器控制台直接查看分析结果：

```js
// 单个技能
SkillAnalyzer.debug(技能对象);

// 单个卡牌（含卡牌扩展字段）
console.log(SkillAnalyzer.analyzeCard(卡牌对象));

// 批量预热（可选）
SkillAnalyzer.preload(所有技能数组);
```

对照期望检查三件事：

1. `type` 是否是你想要的主类型（尤其控制/治疗/伤害）；
2. `power` 是否等于设计数值（不是 30/40/50 这类默认值）；
3. `target` 是否与实际选目标 API 一致。

三项都对了，AI 的行为基本就符合设计意图；否则优先补 `aiHint`，再考虑改描述。

## 七、速查清单

- [ ] `contentCode` 里有 `dealDamage(x, N)` / `heal(x, N)` / `hp -= N` 这类可提取数值
- [ ] 描述里出现具体数字
- [ ] 群体技能写了 `至少命中 2 个`
- [ ] 控制技能没有混用会被 `damage` 抢先匹配的模糊词
- [ ] 非生命回复没有用"回复"二字
- [ ] 减伤/免疫没有用"伤害"二字
- [ ] 需要特殊目标偏好时用 `aiHint.preferTarget`
- [ ] 计谋牌脚本以 `return true` 结尾
- [ ] `preview` 与实际范围一致（否则 AI 的命中数估算会失真）
